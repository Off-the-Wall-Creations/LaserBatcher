LaserBatcher guide

Prepare an SVG that imports and previews clearly

A clear physical size and deliberate styling make an SVG easier to batch and inspect. Prepare those details in your drawing application before uploading.

Give the root SVG a physical size

Set explicit positive Width and Height using in, mm, cm, pt, or pc. Root dimensions expressed only as pixels, unitless numbers or percentages are ambiguous for physical batching and are rejected. A viewBox alone does not establish the physical dimensions.

For a two-inch-wide, one-and-a-half-inch-high design, a root such as <svg width="2in" height="1.5in" viewBox="0 0 192 144"> provides both physical size and drawing coordinates. The viewBox maps coordinates into that size; it does not need to use inches. Keep its proportions and preserveAspectRatio intentional to avoid unexpected empty space or clipping.

Sheet controls use inches and output uses 96 SVG units per inch. Export preserves the source canvas footprint, including whitespace. Resize the page around your design in the drawing application if that whitespace is unwanted.

Make strokes, fills and labels deliberate

  • Use consistent, nonzero strokes and enough contrast to see paths against the preview background.
  • Choose fills and opacity intentionally. An unfilled outline and a solid shape can represent very different artwork.
  • Use explicit operation labels such as Engrave, Score, InteriorCut and ExteriorCut on groups or elements. A plain Cut label cannot choose between interior and exterior cutting.
  • Check compound paths, clipping and transforms in Original preview as well as Enhanced inspection.

Enhanced mapping thumbnails use contrasting colors and non-scaling strokes for inspection only. This avoids changing production styling just to make a small preview readable. The main Source/Batch canvas and exported SVG retain production colors and strokes. Use the mapping panel's Original option to compare.

Keep dependencies inside the SVG

Embed raster images instead of linking to files on your computer or remote URLs. Keep referenced definitions, clipping paths and clone targets in the same document, with unique IDs. Text appearance depends on fonts available in the consuming application; convert text to paths in your editor when exact lettering is essential.

LaserBatcher preserves supported geometry, transforms, IDs and references, namespaces, licensing, hidden content and unknown metadata. Review Hidden content for non-visible material and semantic information. Hidden content is not a substitute for assigning Ignore to visible production artwork.

Check supported-format limits

Simple class-based stroke and fill rules, including the supported Glowforge export pattern, can be resolved for batching. Complex stylesheets and unsupported dependency transformations can block export. External resources and active content are not supported for batching. Use self-contained, static SVG markup and resolve the actionable message shown in Issues.

Recognized Glowforge settings reports appear separately from artwork and retain their original information. Ordinary text remains artwork. Raw machine values and readable report values are shown separately, without assuming a conversion between them.

A file may be valid for metadata-only editing even when it cannot be batched or previewed. That workflow requires an unambiguous supported LaserBatcher metadata record; see the metadata guide.
