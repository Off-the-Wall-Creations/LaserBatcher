LaserBatcher guide

Keep job metadata and estimated runtime with your SVG

Program metadata identifies a job. Estimated Runtime records your own duration estimate for running the entire output SVG once, independently of laser type.

Set program fields and understand yield

Part, Order and Batch are optional. In Create batch, Parts / source is the number of parts represented by one source SVG. Total yield is that number multiplied by Copies. A source representing four parts copied three times produces a total yield of twelve.

The download filename follows [PartName_][Order OrderNumber_][Batch Batch_]xYield.svg. For example, Tag_Order A12_Batch B3_x12.svg identifies a twelve-part output. With no optional fields, the filename is _x12.svg. Runtime is never added to the filename.

Enter an estimate for the whole job

Open Runtime in the toolbar. Enter hours, minutes and seconds, then Apply. Hours can exceed 23, so a duration of 25 hours is valid. Leave the duration blank when it is unknown, or clear it to remove a saved estimate.

The total must be a positive number of whole seconds within the supported range. Negative values, zero duration, fractional seconds and overflow are rejected. The estimate is not multiplied by copy count or yield, and LaserBatcher does not calculate it from geometry or machine settings.

Changes to layout, copies, assignments or operation ordering clear an entered estimate with a notice because the job has changed. Program-field edits and view controls such as zoom, background, collapse and inspection mode retain it. A new batch starts without an output estimate.

Update an existing export without re-batching

  1. Open the generated SVG. A recognized, supported LaserBatcher export defaults to Edit metadata.
  2. Edit Part, Order, Batch, Total yield or Runtime. A saved runtime is restored into the dialog.
  3. Choose Download updated SVG. The filename reflects the edited program fields, and a separate file is downloaded.

Metadata-only editing preserves artwork, layout, sheet dimensions, machine settings, hidden content and unrelated metadata, including unknown JSON properties. XML formatting may change. It does not require operation mapping or sheet-fit validation, and an unavailable preview does not prevent a valid metadata update.

Yield overrides and repeated batches

In Edit metadata, changing Total yield records an explicit override. The original source yield and copy count remain as provenance; changing the number does not add or remove artwork. New and updated records use metadata v2, and existing v1 exports can be read and migrated on update.

To batch a previous export again, select Create batch. Its effective total yield becomes the new source yield: an eight-part export copied three times gives twenty-four parts. An old yield override or runtime estimate is not carried into the new batch.

Resolve filename and metadata conflicts

Valid embedded metadata takes precedence when a file has been renamed. If a valid structured filename disagrees, Issues offers a visible choice between the values, or you can correct the fields before export.

Malformed, ambiguous or future-version records are preserved with a warning. They cannot be safely updated in Edit metadata. For batching, use the filename or enter program fields manually as directed by Issues. Historical nested records remain provenance rather than initializing the current job.
